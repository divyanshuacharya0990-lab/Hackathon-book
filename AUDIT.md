## Corrected issues

| Issue | Correction |
|---|---|
| Broad escalation for routine cross-owner fixes, API decisions, costs and all filled records | Mandatory safeguards separated from routine autonomy; coordinate overlaps and escalate material changes or unapproved spending |
| Full document set required before ordinary work | Minimal context may be drafted from the request; blank templates are not project authority |
| Manual readiness checklist and weak migration transfer guidance | Incoming agent automatically checks access, state, relevant capabilities and dependencies, proceeds when ready and asks only for missing essentials |
| Uncommitted/unpushed work could be lost between machines | Checkpoint captures dirty/untracked work and remote differences; actual patch/bundle/archive transfer is required when applicable |
| Every task implied full release/PR/demo gates | Verification and documentation scale with risk, task and claims; no routine human approval gate |
| Two unsuccessful attempts treated as a hard stop | Pause the failing strategy and try a measurable diagnostic; escalate only actual blockers |
| Prompt paths displayed as plain text and setup guide referenced but absent | All 13 router entries are clickable; setup commands live in the checkpoint or existing project guide |
| Git branches described as sufficient isolation | Separate working directories/worktrees isolate concurrent writers; branch names alone do not |
| Incomplete release truth and security handling | Explicit authorization/visibility checks, no overwrite/force-push, remote SHA/content readback, CI separated from push; untrusted input and integrity/credential remediation guidance |
| Security exceptions could imply waived mandatory safeguards | Documented noncritical test limitations do not waive safeguards or convert unrun checks into passes |
| Uneven evidence vocabulary and unsupported retrospective certainty | PASS/FAIL for executed checks, NOT RUN/NOT ACCESSIBLE otherwise; historical reports separated from reproduced evidence |
| Deadline guidance could silently cut scope or reset shared state | Material MVP cuts escalate, security/integrity remain mandatory, demo resets use isolated test data |
| Navigation and independent prompting burden | Three levels in README, preserved independent prompt guide, one concrete adaptable prompt example |

No vendor pricing, quota amounts, universal file auto-discovery or guaranteed AI memory is asserted. Tool-specific availability, billing and discovery must be checked in the actual environment. No new process-only guides or project-specific dependency are required.

## Reasoning-based usability assessment

These are structured walkthroughs by the auditing assistant, not observed trials with real new developers or an independent second reviewer.

| Scenario | Expected usable route and assessment |
|---|---|
| New solo developer, no history | README → START HERE → Bootstrap. Agent drafts minimal context, verifies capabilities, implements a safe task. No invented teammates or mandatory forms. |
| Existing team joins mid-project | Bootstrap reconciles filled brief, branch/status and checkpoint, names the next outcome and shared dependencies, and starts when accessible. |
| Missing ZIP/repository on a different machine | Migration checks actual access; requests only the missing file/access and preserves source work. Naming an old local path never implies transfer. |
| Chat-only assistant without terminal | Can assess supplied files or propose changes, labels execution inaccessible, and asks for needed capability only when essential. |
| Feature needs a routine cross-module repair | Feature/integration prompts allow compatible authorized repair while coordinating overlaps; material contract or auth changes escalate. |
| Agent loops or hits quotas | Recovery changes diagnostic strategy; checkpoint reserves current state and next action; migration restores actual files rather than memory. |
| Attractive UI with fake verification | UI check traces network/backend/result state and relevant failure cases; screenshots do not establish functional completion. |
| Shared protocol mismatch | Contract template points to executable schemas/fixtures and both producer/consumer checks; material migration decisions involve affected owners. |
| Deadline arrives before full MVP | Scope prompt prioritizes trust/integrity and a narrow honest journey; material cuts escalate, fallback limitations remain clear. |
| Push fails or remote is stale | Git/release prompts preserve local work and distinguish local commit, remote content, PR and CI; no false publication claim. |

The core route is self-contained; optional forms and detailed references do not block routine tasks. The kit cannot guarantee good engineering outcomes or prevent every model error; actual task execution and evidence still matter.
